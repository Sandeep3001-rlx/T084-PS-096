## 2. Problem Statement

Agricultural markets need a reliable system for registering farmer lots, evaluating quality, conducting electronic auctions, checking trader credit eligibility, calculating settlements, tracking payments, and generating financial reports.

This project implements a backend engine to automate these operations while enforcing the business rules specified in the assignment.

## 3. Project Objectives

1. Register farmers, commission agents, traders, and commodities.
2. Register lots and calculate grades and reference prices from assay results.
3. Conduct timed auctions with price floors, bidding increments, and extensions.
4. Validate trader credit exposure and overdue-payment eligibility.
5. Process weigh-in and calculate quality deductions, fees, commissions, and farmer net payable.
6. Handle withdrawals, unsold lots, re-auctions, and bundled lots.
7. Generate auction registers, farmer payment advices, and trader ledgers.
8. Validate input files and produce consistent output.

## 4. Proposed System Architecture

### Command Processor
Reads command files, validates commands, and coordinates the system operations.

### Registration Module
Stores and validates farmer, agent, trader, and commodity records.

### Grading Module
Calculates lot grades and reference prices using assay results and commodity MSP.

### Auction Module
Manages bidding windows, valid bids, price floors, extensions, winner selection, withdrawals, and re-auctions.

### Credit Module
Calculates trader credit limits, checks outstanding dues, evaluates bid eligibility, and tracks suspension status.

### Settlement Module
Processes weigh-in, quality deductions, market fees, agent commission, farmer payments, and penalties.

### Reporting Module
Produces the daily auction register, farmer payment advices, and trader ledgers.

## 5. Data Model

### Farmer
Farmer ID and registration details.

### Commission Agent
Agent ID and registration details.

### Trader
Trader ID, security deposit, credit limit, outstanding dues, payment history, and status.

### Commodity
Commodity ID, name, MSP per quintal, quality parameters, and bidding increment.

### Lot
Lot ID, farmer ID, commodity ID, agent ID if applicable, declared weight, assay results, grade, reference price, and status.

### Bid
Bid ID, lot or bundle ID, trader ID, bid amount per quintal, timestamp, and validation result.

### Auction
Auction ID, lot or bundle ID, opening time, closing time, extension count, valid bids, winner, and result.

### Settlement
Lot ID, actual weight, quality deductions, gross settlement value, market fee, agent commission, farmer net payable, payment deadline, penalties, and payment status.

### Trader Ledger
Trader purchases, market fees, payments, outstanding dues, penalties, deposit encashment, and suspension events.

## 6. Financial Calculation Policy

Python Decimal arithmetic will be used for monetary values.

The implementation will document the order of operations for:

1. Actual settlement weight.
2. Quality deductions.
3. Gross settlement value.
4. Market fee paid by the trader.
5. Commission deducted from the farmer.
6. Farmer net payable.
7. Payment deadlines and overdue penalties.

The precise formulas and rounding rules must be finalized in the business-rule decision log before implementation.

## 7. Input and Output

### Inputs
Farmer, agent, trader, commodity, lot, assay, bid, weigh-in, and payment records supplied through command files.

### Outputs

- Per-lot settlement advice.
- Trader ledger.

The exact file formats will be finalized when the organizer's sample files are supplied.
